# Синхронизация локальной копии с GitHub (Windows)

> Как держать папку на своём компьютере в одном состоянии с репозиторием на GitHub — в обе стороны: ваши новые файлы в `raw/` уходят на GitHub, правки агента в `wiki/` приходят к вам.

## Однократная настройка

1. **Установите GitHub Desktop** — https://desktop.github.com — и войдите в свой аккаунт GitHub. При первом запуске он попросит имя и e-mail для коммитов — заполните.
2. **Установите Git for Windows** — нужен для кнопки `sync.cmd` (GitHub Desktop свой git в систему не добавляет). В PowerShell:
   ```powershell
   winget install --id Git.Git -e
   ```
   или установщик с https://git-scm.com/download/win (все настройки по умолчанию).
3. **Склонируйте репозиторий.** GitHub Desktop → *File → Clone repository → URL*:
   `https://github.com/georgiysaslanov-maker/AI-native-SDLC_with-wiki`
   Папку выберите любую, например `C:\Users\<вы>\SecondBrain`.
4. **Проверьте ветку.** Вверху GitHub Desktop, в поле *Current branch*, должна стоять ветка по умолчанию (основная). Синхронизация работает с той веткой, которая выбрана сейчас.
5. **Первый запуск `sync.cmd`** — дважды кликните по нему в корне папки. При первом обращении к GitHub откроется окно браузера для входа — подтвердите. Дальше вход запоминается.

## Способ 1. Кнопка `sync.cmd` (рекомендуется)

Двойной клик по `sync.cmd` в корне репозитория делает всё сразу:

1. коммитит все ваши изменения (новые файлы в `raw/` и т. п.);
2. забирает изменения с GitHub;
3. отправляет ваши коммиты на GitHub.

В окне видно, что получено и что отправлено. Удобно вынести ярлык на рабочий стол или закрепить на панели задач: ПКМ по `sync.cmd` → *Показать дополнительные параметры → Создать ярлык*, затем перетащите ярлык куда нужно.

## Способ 2. Кнопки GitHub Desktop

Отдельной кнопки «синхронизировать всё» в GitHub Desktop нет, поэтому цикл из двух шагов:

1. **Отправить своё:** слева появятся изменённые файлы → внизу впишите короткое описание (например, «новые материалы в raw») → *Commit to <ветка>* → вверху *Push origin*.
2. **Забрать чужое:** вверху *Fetch origin* → если появилось *Pull origin* — нажмите его.

## Способ 3. Автосинхронизация по расписанию (по желанию)

Если не хочется нажимать вообще ничего — Планировщик заданий Windows будет запускать ту же синхронизацию каждые 10 минут. В PowerShell из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-autosync.ps1             # включить (каждые 10 мин)
powershell -ExecutionPolicy Bypass -File scripts\install-autosync.ps1 -Minutes 30 # другой интервал
powershell -ExecutionPolicy Bypass -File scripts\install-autosync.ps1 -Uninstall  # выключить
```

Права администратора не нужны. Перед включением хотя бы раз запустите `sync.cmd` вручную, чтобы сохранился вход в GitHub. В момент запуска может на долю секунды мелькнуть окно PowerShell. Журнал фоновых запусков — `sync.log` в корне репозитория (в git он не попадает).

## Если случился конфликт

Конфликт бывает, когда один и тот же файл изменён и у вас, и на GitHub (например, вы правили `index.md`, а агент — тоже). Скрипт в этом случае **ничего не затирает**: ваши изменения остаются в локальном коммите, а скрипт сообщает о конфликте и останавливается.

Что делать: откройте GitHub Desktop → *Pull origin* → он покажет конфликтующие файлы → выберите нужную версию или откройте файл в редакторе и сведите вручную → *Continue merge* → *Push origin*. После этого `sync.cmd` снова работает как обычно.

Чтобы конфликтов почти не было: вы кладёте файлы в `raw/`, а `wiki/`, `index.md` и `CHANGELOG.md` правит агент (см. `AGENTS.md`).

## Что лежит где

| Файл | Назначение |
|---|---|
| `sync.cmd` | Кнопка: двойной клик — синхронизация в обе стороны |
| `scripts/sync.ps1` | Сам скрипт синхронизации (commit → pull --rebase → push) |
| `scripts/install-autosync.ps1` | Включение/выключение автосинхронизации в Планировщике заданий |
| `sync.log` | Локальный журнал запусков, в git не попадает |
