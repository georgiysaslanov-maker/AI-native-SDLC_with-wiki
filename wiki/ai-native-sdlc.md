# AI-native SDLC (конвейер разработки с агентами)

> Модель разработки, в которой агент делает черновую работу на каждой стадии, а человек утверждает результат на явных гейтах; каждая стадия оставляет версионируемый артефакт.

## Содержание

### Пять стадий

| Стадия | Вход | Выход | Что фиксирует |
|---|---|---|---|
| Plan | идея / тикет | `intent.md` | что хотим, зачем, ограничения |
| Design | `intent.md` | OpenSpec: `proposal`+`specs` → `design`+`tasks` | требования + дизайн + зоны риска |
| Build | `design`+`tasks` | `tasks.md` с «Планом реализации» + diff | код-обоснованный план → код |
| Test | diff + `tasks.md` | тесты + результаты evals | доказательство корректности |
| Deploy | зелёный PR | находки ревью + merge + запись релиза | ревью, гейт, выкатка |

MAINTAIN (автономная эксплуатация) — будущая фаза, вне текущего охвата методики.

### Девять принципов методики
1. Артефакт — истина и аудит (цепочка коммитов отвечает «кто просил, что сделал агент, кто утвердил»).
2. Человек отвечает за суждение.
3. Верификация важнее генерации.
4. Контекст — ограниченный ресурс (just-in-time).
5. Одно правило — одно место (skills ≠ знания ≠ контракт).
6. Спека первична (SDD), объём пропорционален изменению.
7. Детерминизм там, где нельзя ошибаться (hook, а не только промпт).
8. Вендор-нейтральность.
9. Автономия растёт через зрелость — по метрикам, а не по дате.

### Механика передачи между стадиями
- **Git — истина и гейт:** сигнал «пора утверждать» несёт MR + CODEOWNERS; merge = переход на следующую стадию.
- **Jira — зеркало статуса**, синхронизация всегда git → Jira.
- **Orchestrator** маршрутизирует роли внутри стадии, но эстафету между стадиями несут git и гейты.
- Внутри стадии передача агентная (быстрая); между стадиями — только через человеческий гейт.
- На старте следующую стадию запускает человек; со зрелостью — CI-hook на merge предыдущего артефакта, гейты остаются человеческими.

### Взгляд практиков (митап)
Ожидаемое направление: на каждом этапе SDLC работает специализированный агент (требования → план → код → ревью), а на каждом гейте стоит человек. Без трансформации процессов до и после кодинга LLM даёт лишь **персональную** эффективность.
