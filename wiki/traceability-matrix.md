# Матрица покрытия и трассируемость

> Генерируемый в CI отчёт «требование × тест-кейс × код», сшивающий требования в репозитории и тест-кейсы в TestIT по R-id; сигнал для человека на гейте и элемент DoD.

## Содержание

- Требование без `source` не принимается; матрица сшивается через `R-id` ↔ TestIT-id ↔ автотест (по номеру TC; код сам `R-id` не несёт).
- **Не ведётся руками:** генерируется в CI, прикладывается к PR и/или на дашборд, снапшот — на релиз для аудита.
- **Роль человека:** не строит, а читает как сигнал (есть ли дыры, приемлем ли радиус изменения) и решает по дыре; единственная ручная валидация — легаси-сопоставление R-id ↔ кейс TestIT.
- **Жизненный цикл:** рождается на Design (R-id + source), наполняется на Test, служит гейтом на Deploy.
- Изменение требования флагует связанные тест-кейсы TestIT.
- В polyrepo — пер-сервисная по умолчанию, агрегируется по префиксу `<сервис>/R-n`; для межсервисных фич — отдельное фиче-уровневое E2E-покрытие у оркестратора, склейка по фиче-R-id, без «мегаматрицы».
- Definition of Done включает трассируемость (требование → тест → код).
