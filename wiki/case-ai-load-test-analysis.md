# Кейс: ИИ-анализ нагрузочного тестирования платформы Exolve

> Практика Н. Токарева: агент со скиллами анализирует результаты нагрузочного теста всей платформы Exolve по метрикам и логам и формирует отчёт — время анализа сократилось с часов до ~30 минут.

## Содержание

### Проблема
Тест всей платформы (все услуги одновременно с разной интенсивностью) затрагивает большую часть микросервисов, интеграций и БД: сотни метрик в реальном времени; не все сервисы покрыты метриками — нужно вручную смотреть логи; отчёт собирается вручную.

### Решение
- Подключён Grafana MCP (с интеграцией Loki), простой сабагент и skill для свободного диалога по метрикам и логам («посмотри логи сервиса X за последний час — успешны ли конвертации записей»).
- Два скилла:
  - **master load report** — проход по заранее описанному пайплайну с порогами: очереди RabbitMQ (накопление ready/unacked), статистика звонков (короткие, без ответа, >1% — аномалия), SMS (RPS, time-to-vendor), метрики Locust, троттлинг контейнеров, серверы (IOPS, заполненность диска). Итог — md-отчёт, топ-3 инцидента, открытые вопросы, аномалии в CSV.
  - **master load check** — детальная проверка конкретных цепочек сервисов: кейсы со списком сервисов и инструкций (поиск error, warning, panic в логах, сопоставление трейсов) и вердикт ок/не ок.
- Метрики и пороги выбирает **человек** по методике тестирования; LLM лишь заполнял скилл. Скиллы писались с агентом и валидировались прогонами на результатах с заранее известными проблемами; доработка продолжается.
- Пример находки: голосовые SMS с тишиной — проанализировано с агентом и добавлено в наблюдение.
- Тест повторяется раз в две недели и служит регрессом производительности; текстовые отчёты — артефакты для сравнения.

### Модели и данные
OpenCode + DeepSeek (дёшево, хорошо для выжимки логов). Внешняя модель ходит только в Grafana препрода, где нет ПДн. Возможна настройка на внутренние модели (Qwen 3.5, окно 256K).

### Эффект
- Без аномалий: было ~1 ч просмотра + ~2 ч отчёта → ~30 мин.
- Анализ глубже ручного: можно задавать наводящие вопросы (по trace ID и т.п.), реже нужно звать разработчиков, эффективнее работа по «горячим» данным.
- Точность: шаги в скилле детерминированы («зайди туда, сделай запрос»), мало места для выдумок; за 4 боевых запуска расхождений в анализе не замечено.
- Зона роста — читаемость отчёта и сравнение между запусками.
- Начать просто: клонировать [[qa-agent]], подключить Grafana MCP по инструкции из wiki QA, настроить провайдера.
