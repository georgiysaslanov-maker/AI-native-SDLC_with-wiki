# Организационный доступ к модели

> Решение 1 методики: целевой доступ к LLM — организационный (Enterprise + ключи платформы), а не личные учётки сотрудников; только так контроли периметра централизованы и аудируемы.

## Содержание

### Два пути (методика)
| Критерий | Персональный доступ | Организационный (Enterprise) |
|---|---|---|
| Кто владеет контролями | сотрудник, может отключить | организация, инженер не ослабляет |
| Скан ПДн/секретов, deny-правила | не централизованы | на стороне платформы |
| Обучение на данных | на потребительских тарифах возможно по умолчанию | по умолчанию не используется |
| Логирование, идентичность агента | нет | есть |
| Контроль расходов | нет | админ-панель, лимиты |
| Агент в CI/CD | не под контролем организации | под контролем |
| Соответствие методике | частичное (освоение) | полное |

- Развилка проходит не по линии «чат или агент», а по линии «кто владеет доступом и контролями».
- Личный доступ полезен для освоения агентной работы («фаза погружения») при жёстком правиле: данные клиентов, секреты и репозитории ограниченного доступа — никогда.
- Переход на организационный доступ — предусловие Фазы 0; запускается сразу, т.к. календарно-зависим (закупка, юрформальности).
- До выбора LLM фиксируется только требование: организационный доступ с зоной хранения и без обучения на данных.
- Риск R-14: блокировка Enterprise-аккаунта при следах использования из РФ — принятый риск верхнего уровня, снижается вендор-нейтральностью.

### На митапе
- Корпоративные тарифы по договору не обучаются на данных; срок хранения, по словам выступавшего, «что-то там до 30 дней»; для службы безопасности появляется логирование отправленных сведений. На персональных учётках провайдеры могут обучаться на данных.
- Доступ: большинство фронтир-моделей без VPN недоступны; команда Козлова осваивала split-tunneling. Корпоративный VPN позволяет обращаться к двум фронтир-моделям; Google блокирует аккаунты со «следом из России» (у докладчика был такой опыт). Вопросы VPN «будут решаться с каждой моделью индивидуально и централизованно, где возможно».
- Риск отключения подписок обсуждался и в контексте vendor-lock: «завтра Codex может сказать, что аккаунты из России больше не работают».
- Практики на митапе в основном использовали внешние модели через личные/пробные подписки (GLM на бесплатном периоде, DeepSeek через OpenCode).
- Есть внутренние модели (упоминается Qwen 3.5 с окном 256 тыс. токенов); в планах — развернуть OpenCode внутри: чувствительное — во внутреннюю LLM, нечувствительное — во внешнюю.
