# Контур самопроверки агента

> Способ агента проверить свою работу до того, как её увидит человек: одна команда проверки, измеримая цель, тест-сначала для багфиксов, вывод проверки как часть «готово».

## Содержание

### В методике (стадия Test)
1. Свернуть проверку в одну команду (`make test`) с ненулевым кодом при провале; пример корректного вывода — в контексте репозитория.
2. Дать агенту **измеримую** цель: «все тесты в X зелёные», «скриншот совпадает с макетом», «эндпоинт возвращает 200 с новым полем».
3. Для багфиксов — сначала падающий тест: агент воспроизводит баг тестом, коммитит, затем чинит код, не трогая тест (hook запрещает правку тестов в задаче на исправление).
4. Верификация — часть определения «готово»: прогнать тесты и показать вывод до отчёта о завершении; доказательство прикладывается к PR.
- Антипаттерн: агент, который чинит код, может ослабить проверку, переписав тест.

### На митапе
- И. Румянцев: человек задаёт критерии приёмки, агент сам пишет автотест, проверяет и демонстрирует. В pet-проекте веха считалась готовой, когда все тесты пройдены, Docker-окружение поднимается, автотесты по 12 критериям приёмки проходят, а агент показывает результат по каждому критерию.
- Н. Козлов: автотесты — **базовый гейт** при работе с агентами; снижают стоимость разработки по времени; агент сразу пишет тестопригодный код; тесты — измеримая метрика для агента («сделай хорошо» для него ничего не значит). Агент в команде сам деплоит на тестовый стенд и проходит happy path и пограничные кейсы, определённые заранее с разработчиком; это ломает цикл «разработчик → QA → фикс одного бага → QA».
- Пример Козлова: агент обновил E2E-тесты перед правкой и прогнал 56–58 сценариев в CI — все зелёные; артефакт ушёл в MR и задачу.
- Ловушка (реплика из зала): агент сам пишет тесты на свой код и может поправить тесты, чтобы они проходили, — нужен отдельный гейт независимых тестов.
- «Без человека здесь ничего работать не будет»: если зелёные тесты не проверены человеком — «Бог судья».

## Противоречия

- **Достаточно ли, что агент сам пишет и прогоняет тесты на свою реализацию?**
  - Версия 1 — [[meetup-dpr-2026-10-08]] / `raw/Митап_ДПР_08.10.26_транскрипт.md` ([00:03:32]–[00:03:41], Румянцев): в новую эпоху агент сам пишет автотест на свою реализацию, сам проверяет и демонстрирует.
  - Версия 2 — [[methodology-ai-native-sdlc-exolve]] / `raw/METHODOLOGY-ai-native-sdlc.md` (§4.4, §10.4) и реплика на митапе ([00:59:08]–[00:59:30]): самопроверки недостаточно — критический приёмочный слой пишет человек (AQA), и он недоступен агенту.
  - Комментарий: Румянцев описывает личный проект, где приёмку вёл он сам; методика — корпоративный процесс. Позиции совместимы как «самопроверка + независимый слой», но формулировки расходятся.
