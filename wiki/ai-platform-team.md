# Команда платформы AI-SDLC

> Небольшая платформенная команда, которая даёт продуктовым командам готовые компоненты, стандарты и контроли, но не пишет продуктово-специфичные артефакты за них.

## Содержание

### Зоны ответственности
1. Доступ к моделям и харнесс (L1/L2): API-доступ, слой абстракции, ключи, лимиты, логирование.
2. Контрольный слой: hooks, permissions, sandbox, общие гейты, защита веток.
3. Eval-инфраструктура: прогон evals в CI, golden-датасеты, регрессионные гейты.
4. Каркас знаний: шаблоны intent/spec/plan/review, реестр skills, стандарты контекста.
5. Наблюдаемость и стоимость: AI-телеметрия, дашборды токенов (Prometheus/Grafana/Keep).

### Роли (зоны, не обязательно люди 1:1)
| Роль | Занятость | Единоличная ответственность |
|---|---|---|
| Program / Product owner платформы | part-time | темп и направление программы; accountable за baseline и метрики |
| Platform Tech-lead | выделенная ставка (в Фазе 0 part-time); на старте — человек из команды QA-агента | работоспособность и единообразие платформенных компонентов |
| Eval / Quality owner | part-time, из основателей QA-агента | измеримое качество — данные для решения об автономии |
| Platform / Agent engineer (×1–2) | part-time | работающие hooks, skills, шаблоны |
| DevOps / CI (заимствованный) | по запросу | пайплайн и технические гейты; снятие baseline |
| Локальные эксперты | по одному в каждой команде, вне штата платформы | освоение инструмента в своей команде |

- Ramp-план Tech-lead на 90 дней = вклад в Фазу 0: дни 1–30 — харнесс на opencode, OpenSpec, защита веток; 31–60 — стандарты hooks/evals/skills, продуктовый пресет, build-vs-buy; 61–90 — Build/Deploy на образце, reverse-spec go/no-go, сквозной прогон на двух образцах.
- Обязательные условия: accountable program-owner + выделенный Tech-lead; защищённое время part-time; инженерная глубина — ресурсный запрос №1 (стартовое ядро QA-происхождения, Build/Deploy проработаны слабо); граница «не пишем за команды».
