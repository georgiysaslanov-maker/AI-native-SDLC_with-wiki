# Периметр данных и чувствительные данные

> Правила, какие данные можно отправлять во внешний LLM API: инженерные артефакты уходят (принятый риск), данные клиентов не попадают в контекст агента никогда.

## Содержание

### Два класса данных (методика)
| Тип | Пример | Внешний API | Правило |
|---|---|---|---|
| Данные клиентов | ПДн абонентов, тайна связи, содержимое/метаданные звонков и сообщений, биллинг | ❌ | не попадают в контекст агента; синтетика/обезличивание в тестах; скан на ПДн; ручная работа, пока нет модели в периметре |
| Инженерные артефакты | код, US, proto, spec, план, тест-кейсы | ⚠️ уходят при каждом вызове (R-02) | классификация репозиториев; Enterprise-решение; ограничение инструментов и исходящего трафика |
| Публичные | OSS, публичная документация | ✅ | — |

- Self-hosted моделей нет, поэтому весь обмен идёт через внешний API.
- Перед отправкой diff проходит скан на секреты и ПДн (pre-commit / CI hook) с блокировкой; логи и трейсы, прикладываемые к задаче, маскируются.
- Задачи, реально требующие чувствительных данных, агенту не отдаются; для них может понадобиться локальная LLM.
- Классификация репозиториев («что допустимо отправлять») — открытый вопрос.

### На митапе
- «Код, который вы генерите, не считается чувствительными данными» — его ценность/уникальность не критична. Чувствительные данные — тайна связи и персональные данные.
- Если в dev-окружение не переливают прод-данные, тайны связи и ПДн там нет; если переливают — нужна абстракция, маскирующая данные до отправки в LLM.
- ПДн по закону — набор данных, однозначно идентифицирующий человека (ФИО само по себе — нет; ФИО + телефон или паспорт — да). Выручка — коммерческая тайна: чувствительна, охраняется внутренними документами, но не ПДн. Вопрос о лицевом счёте и действиях пользователя на сайте остался без чёткого ответа.
- Обещана политика/«манифест» с объяснением на примерах; внутри уже есть документы о конфиденциальной информации.
- Токарев: внешняя LLM ходит только в Grafana препрода, где нет ПДн.
