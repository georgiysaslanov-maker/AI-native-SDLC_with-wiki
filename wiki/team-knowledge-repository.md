# Командный репозиторий знаний для агентов

> Практика команды Н. Козлова: отдельный git-репозиторий, где хранятся скиллы, скрипты, MCP, правила, спеки, документация и «память» задач — общий контекст команды для людей и агентов.

## Содержание

### Что внутри
- Монорепозиторий **без кода проектов**: скиллы, скрипты, MCP, правила, спеки, документация для людей и агентов, история выполнения задач («кто что почему делал»), каталог всех репозиториев команды.
- «Память» — md-файлы, индексируемые в SQLite для быстрого поиска (не векторная БД — «не чистый RAG»); используется MCP Basic Memory, память с тегами и связями.
- После задачи автоматически создаётся артефакт-сводка (решения, связи, теги), который через MR попадает в репозиторий; документация обновляется вместе с правками (rules и hooks заставляют агента сделать это в конце цикла), её можно рендерить в Confluence.
- Агент по каталогу клонирует нужные репозитории во временное рабочее окружение, сам создаёт ветку и работает с кодом.

### Принципы команды
1. Изучить рынок и выбрать единый набор инструментов (стек, харнесс) хотя бы в команде.
2. Решить доступ (VPN, split-tunneling).
3. Общий контекст для команды, а не для отдельного человека — разбираться в работе без автора.
4. Доступы агента к рабочему окружению: git, Jira, Confluence, Loki, Grafana, Prometheus (пока test/preprod) — чтобы не копипастить метрики и скриншоты; агент анализирует логи и метрики лучше человека.
5. Собственные действия агента: деплой на тест, проход happy path и пограничных кейсов.
6. Формализация рутины: conventional commits с ключом Jira, MR по шаблону со ссылками, GitFlow, отписка в Jira через skill `jira-writer`.
7. Автоматизация повторяющихся запросов — в skill или быстро написанный инструмент (пример — внутренний сервис MS Admin для управления messaging: журнал действий, роли, альфа-имена, выгрузки в Excel вместо ручной работы в Postman).

### Примеры
- Баг пагинации в MS Admin (ответ падал на лимите 4 МБ): Codex по MCP прочитал задачу в Jira, проверил память на похожие случаи, разобрался в коде, прогнал unit/интеграционные/E2E тесты, собрал образ, задеплоил на тест; 56–58 сценариев зелёные; итоговый отчёт, MR и комментарий в задаче — автоматически.
- Сборка релиза по ~10 микросервисам: агент собирает состав релиза (таблица сервис/задача/автор/MR), diff, закрывает задачи со ссылками.
- Правило бойскаута усиливается: голосом сказать агенту завести задачу техдолга или сразу поправить минорное.

### Переходное состояние
Переход к OpenSpec: PM + агент готовят артефакт с критериями приёмки → разработчик пишет план → техлид ревьюит план до реализации; параллельно QA генерирует тест-кейсы. Пока знания и в Jira, и в GitLab — есть рассинхрон. Кросс-платформенность (codex-first, Cursor через симлинки) — «геморрой».
