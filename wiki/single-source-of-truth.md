# Единый источник истины (git vs Jira/TestIT)

> Для каждого типа артефакта выбирается одно авторитетное место, остальные ссылаются на него; в AI-native модели git становится хранилищем знаний, а Jira — трекером задач.

## Содержание

### Варианты (методика)
1. Репозиторий — источник истины (`.md`), Jira/TestIT ссылаются на коммиты.
2. Легаси-система авторитетна, `.md` — рабочие копии, агент синхронизирует через коннектор.
3. Только перекрёстные ссылки: у `.md` — ID записи, у записи — SHA коммита.

**Принятая модель — перекрёстные ссылки, с решениями по артефактам:**
- Требования — репозиторий (`openspec/specs/`); Jira — трекер задач и статусов, тикет ссылается на спеку, но не содержит её.
- Тест-кейсы — TestIT (агент пишет туда через коннектор), связка с требованиями по R-id.
- Изменение требования помечает связанные тест-кейсы TestIT на регенерацию/ревью.
- Синхронизация статуса — всегда git → Jira; при расхождении прав репозиторий.
- Продукт пишет в репозиторий через обёртку (OpenCode-пресет), не работая с git напрямую.
- Перевод людей на «требование живёт в спеке, а не в тикете» — открытый вопрос трансформации.

### На митапе
- Н. Козлов: у команды единым источником знаний стал git — «самое простое, что версионируется»; агентам и людям ничего ставить не надо. Пока команда в переходном состоянии: знания и в Jira, и в GitLab, есть рассинхрон, «но это уже лучше, чем было».
- Ведущий: «Глобально источник истины должен быть один. Данные не могут дублироваться и в Jira, и в Git»; Jira, «если всё будет хорошо», станет task tracker. Задачи за пределами разработки пока живут в Jira «по старинке» — это трансформация всей компании.
